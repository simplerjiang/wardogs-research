## 本地接口

共享定义：`3_src_driver/abi_protocol.h`。全部为 x64、METHOD_BUFFERED 请求，继续要求原有 `ABI_COMMAND.magic_key`。PEB 和批量读取沿用现有 Windows VM_READ 权限检查，没有增加账号或目标进程白名单。

| 接口 | 编号 | 输入 | 成功输出 |
|---|---|---|---|
| 状态查询 | `0x222014` | 24 字节 `ABI_COMMAND`，仅使用 key | 24 字节 `ABI_STATUS` |
| 进程信息 | `0x222018` | 24 字节 `ABI_COMMAND`，使用 key/PID | 16 字节 `{image_base, peb}` |
| 批量读取 | `0x22201c` | 32 字节 `ABI_BATCH_COMMAND` + count 个 16 字节段描述符 | command.size 字节，按各段 output_offset 排列 |

`ABI_STATUS` 六个 u32 按顺序为：查询协议版本 1、设备就绪标志、单次输出上限 65536、批量段数上限 96、新增接口能力位 7、保留字段 0。版本 1 是这份查询协议的首版，不代表驱动代际从 v3 回退。能力位 1/2/4 分别代表本轮三个新增接口。

`ABI_BATCH_COMMAND = { ABI_COMMAND command; u32 count; u32 reserved; }`，其中 command.size 指定输出总长度，command.address 和 reserved 不使用。段描述符为 `{u64 address; u32 size; u32 output_offset;}`。

批量读取一次获取目标进程引用并检查权限，然后逐段复制；最多 96 段，总输出不超过 64 KiB。先校验并保存全部描述符，再写共享输出缓冲区，因此输出覆盖原请求区域不会改变后续段。没有段覆盖的输出位置置零；重叠输出位置按描述符顺序覆盖。任何一段失败或短复制，整次请求返回失败、Information=0，不向调用者提交部分结果；成功时 Information=command.size。各段不构成时间上原子的快照。

PEB 查询复用旧映像基址读取逻辑，从原生 PEB+0x10 取得基址；旧 `GET_BASE` 的请求和响应布局保持不变。原有客户端仍使用旧读请求，本轮没有将游戏采集改为批量调用。

## 与参考驱动仍不一致

参考依据是此前保存的 `FGTRACK` 驱动文件和反编译记录；其磁盘文件与运行中内核映像的字节身份尚未证明。

| 项目 | 当前本地实现与差异 |
|---|---|
| 设备与协议 | 保留 AbiComm 和 0x222xxx 请求；没有复制参考端四个 WdFilter 设备、0xa92a2xxx 编号或其请求头。因此不能直接替换参考驱动供原客户端使用。 |
| 状态/握手 | 本地返回明确的版本、就绪与能力上限；没有参考端固定握手、最后绑定 PID、查询计数及未确认业务含义的状态字段。 |
| PID 绑定与缓存 | 没有新增 prepare/bind 请求或全局进程缓存；每次查询/每批读取获取并释放目标引用，不复刻参考端“绑定查找失败仍报告成功”。 |
| PEB/基址来源 | 已能返回两者；本地基址仍取自原生 PEB+0x10，参考端使用 PsGetProcessSectionBaseAddress。目标主动修改 PEB 或异常生命周期场景可能有差异；未增加 WOW64 PEB 查询。 |

| 常规读写 | 原有接口保持：本地写入上限 64 KiB，参考常规写入上限 16 KiB；本地没有参考写入失败后的附加进程复制路径。原有单段读取在失败时不报告已传输的部分数据。 |
