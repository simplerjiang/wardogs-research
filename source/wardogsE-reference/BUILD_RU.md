# Сборка — коротко

## 1. Главное: два .sys и кто из них настоящий

| Файл | Размер сейчас | Что это |
|---|---|---|
| `kernel-mode.sys` | 7 168 б | **этот реально маппится в ядро** — путь зашит в маппере (`kernel_mapper.cxx:79`: `<папка kd2.exe>\kernel-mode.sys`) |
| `driver.sys` | 8 704 б | выход сборки драйвера; START.bat проверяет его наличие, на маппинг не влияет |

`kd2.exe` **не читает путь из командной строки**. Строка `kd2.exe driver.sys --auto` —
это `--auto` (режим без пауз) плюс `driver.sys` как исторический маркер. Грузится всегда
`kernel-mode.sys` из папки маппера.

Поэтому правило одно:

> **После каждой сборки драйвера копируй результат в оба имени, `kernel-mode.sys` — первым.**

```bat
copy /Y x64\Release\driver.sys ..\1_run\kernel-mode.sys
copy /Y x64\Release\driver.sys ..\1_run\driver.sys
```

Сейчас в `1_run` пара не выровнена: работает старый `kernel-mode.sys` (7168), рядом лежит
свежий `driver.sys` (8704). Это рабочее состояние — не трогай, пока не решил обновлять
драйвер. Обновление делай целиком: пересобрал → скопировал в оба → перезагрузился → проверил.

## 2. Порядок сборки

### Драйвер (3_src_driver)

```bat
cd 3_src_driver
build_driver.bat
```

Выход: `x64\Release\driver.sys` (8 704 б). Скрипт сам копирует его в `driver.sys` рядом,
в `1_run` — вручную двумя строками выше.

### Чит + оверлей (2_src_cheat)

```bat
cd 2_src_cheat
build_cheat.bat
```

Выход: `WarDogsESP_v2.exe` (379 904 б). Дальше в `1_run`:

1. переименовать в `aDKAF815afjAR.exe` (START.bat ищет ровно это имя);
2. рядом обязательно `WebView2Loader.dll` и `menu.html` — без первого exe не стартует,
   без второго меню откроется пустым.

### Маппер (4_src_mapper) — нужен редко

`kd2_src\kdmapper.sln`, VS2022, **Release x64** → `kd2_src\build\kdmapper.exe`.
Копировать в `1_run` как `kd2.exe`.

В исходнике пакета `--auto` принимается **в любой позиции** (я поправил: выше по течению
проверялся только `argv[1]`, и `kd2.exe driver.sys --auto` уходил в интерактивный режим —
маппер висел на `std::cin.get()`). Если собираешь из своего канона, где правки нет —
вызывай `kd2.exe --auto`, флаг первым аргументом.

## 3. Проверка после замены драйвера

1. **Перезагрузка обязательна.** Драйвер маппится один раз за бут; второй маппинг в том же
   буте = bugcheck `0x109` (PatchGuard).
2. Запустить игру, зайти на сервер, персонаж на карте.
3. `START.bat` → должно дойти до `kernel backend ready` и `Ready. Press F1`.
4. Если `Kernel backend did NOT come up within 30s` — смотри `kdmap.txt`:
   - `ExpCov, CI` → маппер почистил структуру CI → **перезагрузка**, потом снова;
   - `0xc000009a` → уязвимый драйвер заблокирован (HVCI / blocklist / Defender);
   - пусто → отказ UAC.
5. Если после новой пары `kernel-mode.sys`/`driver.sys` бэкенд не поднимается — верни
   старый `kernel-mode.sys` (7168) и перезагрузись. Пара откатывается целиком.

---

## 4. Чего не делать

- не маппить дважды в один бут (0x109);
- не переименовывать `kernel-mode.sys` — маппер ищет имя буквально;
- не подменять только `driver.sys`, оставив старый `kernel-mode.sys` — загрузится старое;
- не запускать второй экземпляр оверлея — маркеры удвоятся, чтения тоже;
- не собирать чит без `menu.html` рядом с exe.
