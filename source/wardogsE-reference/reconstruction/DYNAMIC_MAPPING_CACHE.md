## 实现与证据

| 模块 | 本轮实现 | 静态依据 |
|---|---|---|
| 动态映射 | 每条12字节记录：64位名字标识加32位父索引；匹配21个标识，验证父节点及六条祖先链，允许中间未映射节点 | fgnew 9124 |
| 签名学习 | 从356或448项的固定映射学习21个标识；完整受控 pawn→mesh→骨描述→asset→名字记录路径；成功后不再学习 | 9d80、8a00、4ec0 |
| 映射缓存 | 384槽，键为asset/数组地址/数量；命中不读名字；最大无符号年龄淘汰，同龄选后槽；失败不覆盖旧条目 | 5c18 |
| 姿态缓存 | 192槽、每槽40字节；查找需pawn/mesh/score≥8，写入按pawn更新，优先空槽，满后轮换 | 9654、76e4 |
| 缓存动作 | 早期描述或component拒绝保留缓存；进入选择后的失败清实体槽；写入发生在最终mask清理之前 | 76e4 |
| 上下文变化 | 清两类槽及相关计数器；学习签名和映射命中/未命中累计值保留 | 3536..35c0 |
| 本地停止/重启 | 停止清本地两缓存及签名，停止后产出空帧，重启重新学习 | 本地所有权约定，不能当作参考DLL卸载行为 |

这些名字标识是两个32位值的组合，不是字符串骨名。本轮没有猜测英文骨名，也没有
恢复真实名字池。测试标识由fixture人工生成。

缓存键相同而内容改变时，参考缓存会保留旧映射。本轮明确测试了这一行为；没有增加
TTL、地址代际、自动短读清理或未观察到的校验。真正的实体销毁/地址复用事件仍待分析。

学习阶段8a00在整块读取或父树失败后可以继续候选；5c18先选描述再查缓存，之后失败
不会继续后面的候选。两条失败路径分别实现和验证。

## 受控集成

`ControlledSession` 先用自有356项训练数据学习，再处理96项目标骨数组；后者没有固定
映射表可供回退。目标索引重新排列，修改名字数组地址后关节7从20变为24，绘制仍得到
19条有效连线。窗口消费的mesh确实经过fixture的pawn字段读取。

链路为：受控读取 → 动态映射/384槽缓存 → 姿态选择/192槽缓存 → 投影 → 快照 → 透明窗口。
已有两个骨数组描述同时提供给纯姿态模型。当前集成先物化两份输入，名字解析/变换读取
的调用时序不等于参考76e4逐pass的实时短路时序；缓存命中次数和读取次数只对当前受控
适配器有效，不能据此声称真实读取调度、并发一致性或完整参考函数已恢复。
